0. 优先级与生效范围
优先级：用户输入 > Agent Prompt > user_rules.md > project_rules.md
本规则为项目级强制规则，覆盖默认行为；个人规则仅做偏好补充。
所有输出必须可直接运行、可编译、无语法错误、无明显安全漏洞。
1. 思维与输出约束（必守）
禁止直接甩结果：必须先做需求理解 → 方案设计 → 实现步骤 → 代码 → 验证，关键步骤要写清。
拒绝幻觉与臆造：
不编造不存在的 API、参数、配置项。
不编造版本号、文件路径、环境变量。
不确定时先搜索 / 确认，或明确标注 “待确认”。
一致性与可复现：相同输入 → 相同输出；无随机化、无隐藏逻辑。
精简但完整：不冗余、不缺漏；只给必要代码，注释说明意图，不废话。
中文沟通、英文代码：对话、注释、文档用中文；标识符（变量 / 函数 / 类）用英文。
2. 代码质量规范（通用）
2.1 命名
类 / 接口 / 结构体：大驼峰（UserController、OrderService）
函数 / 方法 / 变量：小驼峰（getUserById、createOrder）
常量：全大写下划线（MAX_PAGE_SIZE、USER_STATUS_ACTIVE）
禁止拼音、无意义缩写（如 sz、xx）；通用缩写可接受（DTO、VO、ID、URL）。
2.2 格式与缩进
前端（JS/TS/Vue/React）：2 空格缩进
后端（Java/Spring Boot）：4 空格缩进
每行一条语句；函数 / 方法长度 ≤ 50 行；嵌套层数 ≤ 3 层
大括号不换行（Java/JS）或统一换行（Python），风格全程一致。
2.3 注释
类 / 接口：说明用途、核心职责、作者 / 时间（可选）
方法：说明参数、返回值、异常、核心逻辑（JSDoc/JavaDoc）
关键逻辑、边界条件、复杂算法：必须行内注释；冗余注释（如 // 定义变量）禁止。
2.4 结构与复用
遵循单一职责：一个函数 / 类只做一件事。
遵循 DRY：公共逻辑抽成工具 / 方法，禁止复制粘贴。
分层清晰：控制器 → 服务 → 数据层；职责不交叉。
3. 安全规范（强制）
输入必校验：所有外部输入（参数、请求体、URL、Cookie）必须做类型 / 长度 / 格式 / 合法性校验。
防注入：SQL/NoSQL/Shell 必须用参数化查询 / ORM，禁止拼接字符串。
防 XSS：前端输出必须转义；后端返回敏感数据不直接注入 HTML。
敏感信息：密码、密钥、Token 禁止硬编码；统一用环境变量 / 配置文件。
异常处理：捕获异常但不暴露栈信息；返回统一错误码 + 友好提示。
4. 技术栈与框架约束
默认技术栈（可按项目改）
前端：Vue3 + TypeScript + Vite + Element Plus
后端：Java(SpringBoot)/Python(FastAPI) + MySQL + Redis
版本约束：使用稳定版，不盲目追新；避免废弃 API。
第三方依赖：优先官方 / 主流包；引入前说明用途与必要性；版本锁定。
5. 文件与目录规范
遵循项目现有目录结构；无结构时按标准分层：
plaintext
src/
  ├── components/  # 公共组件
  ├── pages/       # 页面
  ├── services/    # API请求
  ├── utils/        # 工具函数
  ├── hooks/        # 自定义Hook
  └── assets/       # 静态资源
新增文件必须归类存放；命名清晰（如 user.service.ts、OrderList.vue）。
6. 输出交付规范
代码块必须完整、可直接复制运行，不省略关键部分。
提供必要说明：用途、依赖、运行命令、配置要点。
复杂需求分多步输出：先结构 / 接口，再核心逻辑，最后细节优化。
输出前自校验：语法、编译、安全、规范一致性。
